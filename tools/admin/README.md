# Адмінка сайту: як редагувати сайт і вести замовлення самому

Адреса: **https://cas-develop.com/kabinet/admin**

Тут можна без програміста й без Claude:

- вести **CRM** — замовлення Оздоби й заявки з сайту, статуси, відповідальних, нотатки, суми, дати дзвінків;
- редагувати **товари Оздоби**, **статті блогу**, **сторінки послуг (лендинги)**, **меню й футер**, **тексти звичайних сторінок**;
- завантажувати **фото**;
- дивитися **історію змін** і **відкочувати** невдалі правки;
- вести **проєкти клієнтів**: етапи, фотозвіти, документи (клієнт бачить їх у своєму кабінеті).

---

## 1. Як зайти

1. Відкрийте https://cas-develop.com/kabinet/admin.
2. Увійдіть через **Telegram**, **Google** або **номер телефону** (так само, як клієнти).
3. Доступ є лише в адміністраторів: їхні Telegram-ID і пошти записані в секретах GitHub
   `SHOP_ADMIN_TG_IDS` і `SHOP_ADMIN_EMAILS` (через кому). Щоб додати менеджера — допишіть туди його ID чи пошту
   (GitHub → репозиторій → Settings → Secrets and variables → Actions) і зробіть будь-яку зміну на сайті, щоб пройшов деплой.

Кожен запит адмінки сервер перевіряє окремо: без входу адміністратора нічого не читається й не змінюється.

## 3. Як працює збереження

1. Натискаєте **Зберегти** → сервер записує зміну в GitHub одним «комітом» (як фото «до/після» у історії).
2. GitHub сам перезбирає сторінки з цих даних і викладає сайт на Cloudflare. Це **2–4 хвилини**.
3. У вкладці **Історія** видно статус збірки: «ок» — зміни вже на сайті; «йде…» — зачекайте; «помилка» — див. розділ 5.

Якщо хтось (ви в іншій вкладці, Claude чи інший менеджер) змінив той самий файл раніше — адмінка не перезапише його,
а скаже «Файл уже змінено». Оновіть сторінку й повторіть.

Адмінка може змінювати лише контент: товари, статті, лендинги, меню, тексти сторінок, фото. Код сайту, налаштування
й бази даних вона змінити не може — це захист від випадкових поломок.

## 4. Токен GitHub (потрібен для редагування сайту)

Без токена працюють CRM, замовлення, клієнти, проєкти й коди партнерів, а вкладки редагування пишуть «Потрібен токен».

Створити токен (одноразово, ~5 хвилин):

1. Увійдіть на https://github.com під акаунтом, якому належить репозиторій `chinaoptshop-code/cas-development-site`.
2. Відкрийте https://github.com/settings/personal-access-tokens/new (Settings → Developer settings →
   Personal access tokens → **Fine-grained tokens** → **Generate new token**).
3. Заповніть:
   - **Token name**: `cas-admin`
   - **Expiration**: 1 рік (або «No expiration»). Запишіть у календар дату, коли треба буде створити новий.
   - **Repository access**: **Only select repositories** → виберіть лише `cas-development-site`.
   - **Permissions → Repository permissions**:
     - **Contents** — **Read and write** (обовʼязково);
     - **Actions** — **Read-only** (необовʼязково: щоб в «Історії» було видно статус збірки);
     - **Metadata** — Read-only (ставиться сам).
4. **Generate token** → скопіюйте рядок, що починається з `github_pat_…` (його показують один раз).
5. Відкрийте репозиторій → **Settings → Secrets and variables → Actions → New repository secret**:
   - **Name**: `SHOP_GITHUB_CONTENT_TOKEN`
   - **Secret**: вставте токен → **Add secret**.
6. Запустіть деплой, щоб сайт отримав токен: вкладка **Actions** → «🚀 Deploy to Cloudflare Pages» → **Run workflow**.
7. Через 2–3 хвилини оновіть /kabinet/admin — вкладки редагування запрацюють.

Токен нікуди більше не вставляйте й нікому не пересилайте. Якщо він «засвітився» — видаліть його на тій самій сторінці
GitHub і створіть новий (кроки 2–6).

## 5. Якщо збірка впала (в «Історії» — «помилка»)

На сайті в цей час лишається **попередня робоча версія** — нічого не ламається для відвідувачів.

1. В «Історії» знайдіть свою останню зміну й натисніть **Відкотити**. Через 2–4 хвилини збірка пройде знову.
2. Подивитися причину: натисніть на червону позначку «помилка» → відкриється сторінка GitHub Actions → крок з ❌ →
   останні рядки. Найчастіше:
   - `❌ tools/blog/articles/…: …` — у статті бракує поля, фото не знайдено, опис довший за 160 символів,
     два фото поспіль чи фото на початку тексту. Виправте статтю й збережіть знову;
   - `немає фото … для товару …` — фото товару не завантажилось; видаліть і додайте фото ще раз;
   - помилка JSON у лендингу — у вкладці «Лендинги» відкрийте сторінку, перемкніться на «JSON» і виправте.
3. Якщо незрозуміло — надішліть посилання на сторінку помилки Claude чи розробнику.

## 6. Як відкотити будь-яку зміну

Вкладка **Історія** → рядок зі зміною → **Відкотити**. Створиться новий запис, що повертає файли до стану «до».
Нічого не губиться: відкат теж можна відкотити.

Якщо адмінка пише «Ці файли змінювали пізніше» — спершу відкотіть новіші зміни тих самих файлів (вони вище в списку).
Автоматичні записи «[rebuild]» (перезбірка сторінок) не відкочуються — відкочуйте зміну, яка їх викликала.

## 7. CRM і Google-таблиця

- Замовлення з кошика Оздоби потрапляють у CRM автоматично.
- Заявки з форм сайту потрапляють у CRM автоматично: форма надсилає їх одночасно на сайт (`/api/leads`) і в n8n
  (старий ланцюжок «Contact Form → Telegram» працює як раніше). Якщо n8n теж пересилає заявку на `/api/leads` —
  дубля не буде: та сама заявка з того самого номера за 10 хв записується один раз.
- Google-таблиця **«CAS — CRM замовлень»** (папка з іншими таблицями CAS CRM у Google Drive): аркуші «Замовлення»,
  «Клієнти», «Товари», «Постачальники», «Як працює». У n8n є workflow
  «CAS — заявки й замовлення сайту → Google Sheets (CRM)»: він додає рядок у «Замовлення». Щоб він працював
  на кожну заявку, у workflow «Contact Form → Telegram» додайте наприкінці вузол **HTTP Request** (POST
  `https://n8n.china-opt-shop.pp.ua/webhook/cas-crm-sheet`, тіло — той самий JSON) або **Execute Workflow**,
  і активуйте новий workflow (перемикач Active).

## 8. Сповіщення про заявки (Telegram, 15 хвилин)

**Що відбувається саме:**

1. Хтось залишає номер на сайті або оформлює замовлення в Оздобі → за кілька секунд **кожному адміну** (Telegram-ID із
   `SHOP_ADMIN_TG_IDS`) бот сайту пише: послуга, сторінка, телефон (натисніть на номер — Telegram запропонує подзвонити),
   імʼя, коментар, UTM, час. Під повідомленням дві кнопки:
   - **✅ Взяв у роботу** — заявка стає «В роботі», відповідальний — той, хто натиснув, рахується **час реакції**
     (хвилини від заявки до натискання). У всіх адмінів повідомлення змінюється на «✅ Взяв <імʼя> за N хв».
     Хтось уже взяв — бот так і скаже;
   - **📋 Відкрити в CRM** — адмінка на вкладці CRM.
   Перетягнути картку з «Нове» в будь-яку іншу колонку CRM — те саме, що натиснути «Взяв у роботу».
2. Якщо за **15 хвилин** ніхто не взяв — нагадування «⏰ Заявка без відповіді 15 хв…», ще за **60 хвилин** — друге
   (і все, далі — у вечірньому звіті). **Уночі (22:00–08:00 за Києвом) нагадувань немає** — вони приходять о 08:00.
   Сама заявка приходить завжди, і вночі теж.
3. О **20:45** — звіт за день: скільки заявок і замовлень, скільки взято, середній і максимальний час реакції, скільки
   вклалися в 15 хв і які заявки лишилися без відповіді.
4. Час реакції видно в CRM: на картці (⏱, червоним — якщо більше 15 хв), у таблиці (колонка «Реакція»), у картці
   заявки й у CSV.

**Що треба зробити Михайлу:**

- **Кожен адмін один раз відкриває бота сайту в Telegram і натискає «Start»** (без цього Telegram не дозволяє ботові
  писати першим). Бот відповість «Готово: сюди приходитимуть нові заявки…».
- Секрети `SHOP_TELEGRAM_BOT_TOKEN` і `SHOP_ADMIN_TG_IDS` уже є — для миттєвих сповіщень більше нічого не потрібно.
- Для нагадувань, звіту й кнопки «Взяв у роботу» потрібен секрет **`SHOP_LEAD_INGEST_KEY`**. Якщо його ще немає:
  1. Придумайте довгий випадковий рядок (30+ латинських літер і цифр, наприклад з менеджера паролів).
  2. GitHub → репозиторій → **Settings → Secrets and variables → Actions → New repository secret**:
     Name `SHOP_LEAD_INGEST_KEY`, Secret — цей рядок → **Add secret**.
  3. **Actions** → «🚀 Deploy to Cloudflare Pages» → **Run workflow** (сайт отримає ключ).
  4. Готово: **Actions** → «⏰ Заявки — SLA 15 хв і звіт» запускається сам кожні 5 хвилин (GitHub іноді запізнюється на
     кілька хвилин — це нормально). Перший запуск сам підключить кнопки бота (вебхук).
- Кнопка «Взяв у роботу» нічого не робить? Отже, оновлення бота забирає інша програма (наприклад, n8n з Telegram Trigger
  для цього ж бота). Тоді: **Actions** → «⏰ Заявки — SLA 15 хв і звіт» → **Run workflow** → `webhook` — бот перейде на
  сайт (вхід на сайт за номером телефону бот сайту теж обробляє сам). Звіт за сьогодні вручну — те саме з `report`.

**Для розробника:** `functions/_alerts.js` (тексти, кнопки, SLA, звіт, вебхук), `functions/api/tg/webhook.js`
(кнопка «Взяв у роботу» лише від `ADMIN_TG_IDS`; вхід за номером за протоколом `tools/shop/PHONE_LOGIN.md`; Telegram
підписує запити заголовком `X-Telegram-Bot-Api-Secret-Token`, виведеним з токена бота), `functions/api/admin/lead-sla.js`
(ключ `x-lead-key`), `.github/workflows/lead-sla.yml`, міграція `migrations/0006_lead_alerts.sql` (`taken_at`,
`reaction_min`, `reminders`, `tg_alerts`). Нагадування й звіт — лише для заявок, про які бот сповіщав (не для внесених
вручну й не для старих). Локальна перевірка: `wrangler pages dev` з `.dev.vars` (`TELEGRAM_API_BASE` — адреса мок-сервера
Bot API, `ALERTS_TEST_CLOCK=1` — дозволяє підміняти час полем `now` у `lead-sla`); у продакшні ці дві змінні не задаються.

## 10. Безпека (аудит 25.10.2026)

- **Усі `/api/*`** проходять `functions/api/_middleware.js`: зміни (POST/PATCH/DELETE) — лише з нашого Origin
  (cas-develop.com / той самий хост), не `Sec-Fetch-Site: cross-site`, тіло — лише `application/json` (інакше 403/415);
  тіло до 64 КБ (редактор — до 31 МБ); відповіді з `nosniff`, `X-Frame-Options: DENY`, CSP `default-src 'none'`, без CORS.
- **Сесія** `cas_s`: HttpOnly, Secure, SameSite=Lax, підпис HMAC; клієнт — 30 днів, **адмін — 7 днів** (старіші адмінські
  cookie не приймаються — увійти заново). Секрет підпису — `SHOP_SESSION_SECRET` (необовʼязково; його зміна = вихід усіх).
- **Ліміти** (`functions/_rate.js`, таблиця `rate_hits`, міграція 0007; IPv6 — за /64): заявки 5/год з IP, замовлення 10/год,
  перевірка коду партнера 20/год (і окремо 20/год замовлень з кодом), вхід Telegram/Google 30/год, вхід за номером 5/год.
- **Антиспам форми** без капчі: приховане поле `hp` і `t_ms` (заявка швидше 1,5 с після відкриття сторінки — бот);
  бот бачить «успіх», заявка не зберігається.
- **Заголовки сторінок** — `_headers` (CSP з переліком реальних джерел; для `/kabinet*` — ще `'unsafe-eval'` для віджета
  Telegram; для `/kabinet/admin*` — `frame-ancestors 'none'`, `no-referrer`). Нове зовнішнє джерело (скрипт, iframe,
  API) — спершу додати в CSP у `_headers`, інакше браузер його заблокує.
- CSV-експорт CRM екранує формули (`=`, `+`, `-`, `@`); клієнт у `/api/orders` бачить лише свої поля (без `crm_note`).

## 11. Онлайн-контроль обʼєкта (кабінет клієнта /kabinet/obiekt)

Клієнт бачить свій обʼєкт: етапи зі статусами й прогресом, стрічку фотозвітів, акти етапів і документи, графік платежів
і камеру 24/7. Публічне демо з вигаданим «Демо-обʼєктом» — https://cas-develop.com/onlain-kontrol (і /ru/onlain-kontrol).
Усе вносить менеджер в адмінці: **Проєкти клієнтів** → виберіть клієнта → відкрийте проєкт (або **+ Проєкт**).

**Етапи.** У блоці «Етапи: статус і прогрес» — назва, статус (заплановано / в роботі / приймання / виконано / пауза),
повзунок відсотка, дати, примітка; **+ етап** — новий. Натисніть **Зберегти проєкт** — тоді етап отримає внутрішній id,
і до нього можна привʼязати фотозвіт, акт чи платіж (у списках «Етап» нові етапи зʼявляються після збереження).

**Фотозвіт (раз на 1–2 тижні).** Під «Фотозвіти»: дата, заголовок («Тиждень 5: стяжка»), **Етап**, опис. Фото:
- кнопка **Завантажити фото** (потрібен токен GitHub, розділ 4) — фото стискаються у WebP, кладуться в `img/uploads`,
  посилання підставляються самі; на сайті фото зʼявляться за 2–4 хв після збірки;
- або вставте https-посилання, по одному в рядку (Google Drive з доступом «за посиланням», власне хмарне сховище).
Потім **Додати фотозвіт**. Клієнт бачить звіт у стрічці; кнопка біля етапу фільтрує звіти цього етапу.

**Акт етапу.** У «Документи»: тип **Акт етапу**, етап, назва («Акт етапу 2»), посилання на PDF → **Додати документ**.

**Графік платежів.** Схема в кожного клієнта своя: заповніть рядок (назва, етап, %, сума й валюта, дата за планом,
статус, примітка) → **Додати платіж**, або натисніть заготовку **50/50**, **50/30/20**, **50/40/10** — додадуться рядки з %,
далі вкажіть суми й дати. Статус і дату можна міняти прямо в таблиці; «Оплачено» ставить фактичну дату сам.

**Камера 24/7 (за доп. оплату; ціну на сайті не вказуємо — «за запитом»).** Поле **Камера 24/7 — посилання** у формі проєкту
→ **Зберегти проєкт**. Що вставляти:
- **YouTube-трансляція** з доступом «за посиланням» (`https://youtube.com/live/…` або `https://youtu.be/…`) — відтворюється
  прямо в кабінеті (через youtube-nocookie.com; вмикається лише після натискання клієнтом);
- **пряме посилання на кадр** `.jpg/.png/.webp` (деякі камери/NVR дають «snapshot URL») — кадр з кнопкою «Оновити кадр»;
- **будь-яке інше** https-посилання хмари камери (Ezviz, Hik-Connect, Imou, Ivideon…) — у кабінеті кнопка «Відкрити камеру»
  (нова вкладка). У «Підказці до камери» напишіть, як увійти (напр. «застосунок Ezviz, вхід за вашим номером»).
Лише `https://`, без логіна й пароля в адресі (такі посилання адмінка не прийме). Посилання бачить тільки цей клієнт —
але воно працює для будь-кого, хто його має, тож для хмар камер краще давати клієнту доступ у застосунку, а сюди — посилання
на сам застосунок/сайт. Порожнє поле — клієнт бачить картку «Підключити камеру 24/7» з кнопкою заявки
(заявка приходить у CRM і Telegram з послугою `camera`).

**Для розробника.** Міграція `migrations/0008_online_control.sql` (`projects.camera_url/camera_note`, `project_reports.stage_id`,
`documents.stage_id`, таблиця `project_payments`; застосовується під час деплою). API: `GET /api/account/projects` (лише проєкти
сесії; ліміт 600/год з IP) і `/api/admin/projects` (лише адміни; `type: 'payment'`, поля камери й `stage_id`; записи 600/год).
Розбір посилання камери — `cameraOf()` у `functions/_account.js`. Інтерфейс: `assets/kabinet.v2.js` (`objectTab`),
`assets/admin/cms.v1.js` (`projectForm`). CSP не розширювали: YouTube уже є у `frame-src`, решта камер відкривається в новій вкладці.
