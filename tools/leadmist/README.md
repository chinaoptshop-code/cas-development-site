# LeadMist / ЛідМіст — MVP (фаза 1)

Закрита B2B-біржа: компанії дизайну, архітектури, будівництва, ремонту й нерухомості передають одна одній клієнтів, яких не беруть, і отримують 5–15% від угоди.
Основний інтерфейс — Telegram-бот, плюс простий лендинг і сторінка згоди клієнта. ТЗ: Google Doc «ТЗ v1 — платформа обміну клієнтами».

Рішення власника (16.11.2026): назва LeadMist / ЛідМіст; окремий бренд (без CAS в інтерфейсі); старт в Україні, інтерфейс українською (готовий до інших мов);
комісія рекомендувачу 5–15% задається для кожного ліда; плата платформи — 15% від комісії рекомендувача, мінімум $50 за угоду, платить отримувач.

> Код лежить у `tools/leadmist/` репозиторію сайту лише тимчасово: тека `tools/` видаляється перед деплоєм сайту, тож на сайт CAS це не потрапляє.
> Для запуску продукту — винести в окремий репозиторій і окремий проєкт Cloudflare (див. ТЗ, п. 6.1).

## Архітектура

Один Cloudflare Worker (TypeScript, без залежностей у рантаймі) + D1 + Cron Trigger.

| Шлях | Що робить |
| --- | --- |
| `POST /tg/webhook` | вебхук Telegram (перевірка заголовка `X-Telegram-Bot-Api-Secret-Token`) |
| `GET /` | лендинг |
| `GET /terms` | умови (чернетка для юриста) з версіями текстів |
| `GET/POST /c/<token>` | сторінка згоди клієнта: «Погоджуюся» / «Не погоджуюся» / «Відкликати згоду» |
| `GET /health` | перевірка |
| cron `17 * * * *` | друга хвиля розсилки, строки, 72 год на згоду, 24 год на контакт, нагадування 14/30 днів, прибирання |

Файли:

- `src/index.ts` — роутер і cron; `src/bot.ts` — діалоги бота й кнопки; `src/services.ts` — уся бізнес-логіка;
- `src/pii.ts` — автоперевірка примітки на телефони, e-mail, посилання, @нікі, адреси, імена, коди; ключ дедуплікації клієнта;
- `src/matching.ts` — підбір: тип робіт ∩ регіон ∩ бюджет ∩ активний ∩ не сам ∩ не на паузі; сортування рейтинг → швидкість реакції → закриті угоди; топ-5 з ексклюзивом 24 год, далі всім;
- `src/commission.ts` — комісія з кожного траншу клієнта; плата платформи 15%, мінімум $50 на угоду (рахується від сумарної комісії, тож мінімум береться один раз);
- `src/state.ts` — машина станів угоди й хто може робити переходи; `src/gating.ts` — розкриття контакту лише після акцепту з OTP **і** згоди клієнта;
- `src/crypto.ts` — AES-GCM для контактів, HMAC для хешу контакту й OTP; `src/pages.ts` — сторінки; `src/admin.ts` — CSV-експорт;
- `src/i18n/uk.ts` — усі тексти (нова мова — скопіювати файл і зареєструвати в `src/i18n/index.ts`);
- `migrations/0001_init.sql` — схема D1.

Таблиці: `members` (компанія, ЄДРПОУ/РНОКПП, типи робіт, регіони, діапазон бюджетів, `verified`, статус, рейтинг), `leads` (анонімна картка, комісія %, статус, хвиля, хеш клієнта, дубль),
`lead_contacts` (лише шифротекст, строк зберігання 24 міс.), `lead_offers` (розсилка, ексклюзив), `acceptances` (версія умов, час, Telegram ID, OTP), `otps`,
`deals` + `deal_events`, `client_consents` (метод, версія тексту, час, IP, User-Agent, відмова/відкликання), `payments`, `commissions`, `ratings`, `audit_log`, `bot_sessions`.

### Як проходить лід

1. Вступ: `/start` → назва, ЄДРПОУ/РНОКПП, контактна особа, типи робіт, регіони, бюджети, портфоліо → акцепт оферти платформи з одноразовим кодом → модерація (кнопки «Схвалити/Відхилити» адмінам).
2. «Передати клієнта»: тип робіт, регіон, площа (м² або сотки для ландшафту), бюджет, старт, примітка (з ПД — відхиляється), комісія 5–15%, контакт клієнта (шифрується одразу).
3. Підбір і розсилка топ-5 (ексклюзив 24 год); якщо ніхто не взяв — cron розсилає всім відповідним. Строк дії ліда — 7 днів.
4. «Взяти» → умови по ліду → «Приймаю» → одноразовий код → бронювання (лише один отримувач, захист від гонки умовним `UPDATE`). Новим учасникам (перші 30 днів) — не більше 3 «Взяти» на добу.
5. Рекомендувач отримує посилання `/c/<token>` і пересилає клієнту зі свого телефону. Альтернатива MVP — кнопка «Клієнт погодився усно» (позначка `manual`).
6. Після згоди бот надсилає контакт отримувачу (запис `contact.reveal` в журналі). Без згоди за 72 год бронювання скасовується, лід повертається в біржу; без «Зв’язався» за 24 год — теж.
7. Статуси кнопками: зв’язався → зустріч → договір (сума) → оплата клієнта (кожен транш) → комісію виплачено (підтверджує рекомендувач) → закрито. Бічні: відмова клієнта, не вийшло на зв’язок, спір, скасовано.
8. Нагадування: 14 днів без змін — отримувачу, 30 днів — адмінам.

Адмін-команди (Telegram ID з `ADMIN_TG_IDS`): `/pending`, `/approve ID`, `/reject ID`, `/block ID`, `/leads [статус]`, `/deals`, `/export members|leads|deals|commissions` (CSV без контактів клієнтів).
Учасникам: `/pause N` (не брати лідів N днів), `/resume`, `/cancel`, `/help`.

## Перевірка

```bash
cd tools/leadmist
npm ci
npm test            # vitest: PII, підбір, комісії (з мінімумом $50), машина станів, gating згоди + наскрізні сценарії
npm run typecheck   # tsc
npm run smoke       # wrangler dev (workerd + локальна D1) + мок Telegram API: лендинг, 403 без секрету, фейковий /start, cron
```

Наскрізні тести (`test/flow.test.ts`) ганяють справжній `fetch`-обробник Worker'а з D1 на `node:sqlite` і підміненим Bot API:
вступ 4 компаній → модерація → лід із ПД відхилено → лід опубліковано (контакт у БД зашифровано) → розсилка лише відповідним → «Взяти» з OTP →
сторінка згоди (маска контакту) → розкриття лише після згоди → статуси → 2 транші по $22 000 (комісія $2 200 + $2 200, платформа $330 + $330) → підтвердження виплат → закриття → CSV;
а також друга хвиля через 24 год, строк 7 днів, 72 год без згоди, відмова клієнта, усна згода, дубль клієнта. Усі дані у тестах вигадані.

## Що потрібно від Михайла для запуску

1. **Бот**: у @BotFather створити бота (назва «ЛідМіст», username на зразок `LeadMistBot`/`LidMistBot` — перевірити, що вільний), отримати токен.
2. **Cloudflare** (окремий акаунт або окремий проєкт, безкоштовного плану досить):
   ```bash
   cd tools/leadmist && npm ci
   npx wrangler login
   npx wrangler d1 create leadmist            # database_id → у wrangler.toml
   npm run db:migrate:remote
   npx wrangler secret put TELEGRAM_BOT_TOKEN
   npx wrangler secret put TELEGRAM_WEBHOOK_SECRET   # openssl rand -hex 32
   npx wrangler secret put CONTACT_KEY               # openssl rand -base64 32
   npx wrangler secret put HASH_KEY                  # openssl rand -hex 32
   npm run deploy
   ```
   У `wrangler.toml` вписати `PUBLIC_URL` (адресу `*.workers.dev`), `BOT_USERNAME`, `ADMIN_TG_IDS` (свій Telegram ID і модератора).
3. **Вебхук**:
   ```bash
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
     -d url=https://<worker>.workers.dev/tg/webhook -d secret_token=<TELEGRAM_WEBHOOK_SECRET> \
     -d 'allowed_updates=["message","callback_query"]'
   ```
4. **Юрист**: тексти оферти платформи, додатка по ліду (агентський договір), згоди клієнта й політики ПД; після погодження — оновити `/terms`, `TERMS_VERSION`, `LEAD_TERMS_VERSION`, `CONSENT_VERSION`.
5. **Рішення з відкритих питань ТЗ** (п. 9): юрособа платформи і ПДВ, база комісії (з ПДВ/без, лише роботи чи все), anti-bypass 24 міс., чи лишати «усну згоду» в MVP, хто модератор.
6. **Домен — пізніше** (поки `*.workers.dev`); після реєстрації — Custom Domain у Cloudflare і новий `PUBLIC_URL` + повторний `setWebhook`.

Ключ `CONTACT_KEY` після запуску не змінювати: інакше вже збережені контакти не розшифруються (ротація — окрема задача).

## Зроблено / далі

Зроблено (тиждень 1 + основа тижня 2): схема D1, вступ і модерація, акцепти з OTP, картка ліда з автоперевіркою ПД, шифрування й дедуплікація контактів,
підбір і дві хвилі розсилки, «Взяти» з лімітом для нових, згода клієнта (посилання й усна), розкриття з журналом, статуси угоди, транші й нарахування комісій,
підтвердження виплат, нагадування й тайм-аути через cron, адмін-команди, CSV, лендинг, тести.

Далі (тиждень 3):
- рейтинги: запит оцінки 1–5 після закриття/відмови (таблиця `ratings` є), перерахунок `rating_avg`, метрики профілю (конверсія, % вчасних виплат, спори);
- anti-bypass: контрольні пінги клієнту через 30 і 90 днів (потрібен канал до клієнта з його згоди), заява «клієнт уже був мій» за 48 год, вибіркові перевірки договорів;
- спори: відкриття з бота, черга модератора, рішення з причиною;
- адмінпанель у вебі (перегляд черг, ручні зміни статусів і нарахувань, звіти: ліди за тиждень, конверсія, GMV, плата платформи, боржники), рахунки платформи;
- захист: rate-limit на вебхук і сторінку згоди, щоденні бекапи D1, R2 для доказів згоди;
- пілот на 10 учасниках, потім 30–50.
