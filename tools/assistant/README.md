# Персональний помічник Михайла

Помічник живе в Claude Code (хмарні сесії) і спілкується з Михайлом через Telegram.
Його «мозок» — сценарії в `playbooks/`, «руки» — скрипти в `bin/` та інструмент
`tools/telegram/tg.sh`, «пам'ять» — папка **«Асистент Михайла»** у Google Drive.
Цей репозиторій публічний, тому тут лише код і сценарії, жодних особистих даних.

## Що вміє

| Напрям | Що робить | Сценарій |
|---|---|---|
| Вхідні | читає наш чат щогодини (8:00–22:00), розуміє текст і голосові, виконує: задача, нагадування, подія в календарі, пошук у Telegram, пошта, конспект, PDF | `playbooks/inbox.md` |
| Ранок | о 07:30 брифінг: календар, 3 головні задачі, спортзал, хто чекає відповіді в Telegram і пошті | `playbooks/morning.md` |
| Вечір | о 21:00 підсумок дня, відмітки звичок, план на завтра, питання для розвитку | `playbooks/evening.md` |
| Тиждень | у неділю о 18:00 огляд тижня у PDF: факти, висновки, план, стан компанії | `playbooks/weekly.md` |
| Спортзал | за 30 хв до тренування: що сьогодні, минулі ваги, серія; облік пропусків | `playbooks/gym.md` |
| Зустрічі | запис Plaud або голосове → транскрипт → конспект з рішеннями і діями → PDF, задачі, календар | `playbooks/meeting-notes.md` |
| Читання | тези по розділах, картки для повторення, черга книг, відкладені статті | `playbooks/reading.md` |
| Документи | будь-який текст → акуратний PDF (кирилиця, A4) → у Telegram і Drive | `playbooks/pdf.md` |
| Компанія | проєкти, воронка, хто з клієнтів чекає відповіді, КП та тези для клієнтів, правки сайту | `playbooks/company.md` |
| Правила | мова, тон, пам'ять, безпека | `playbooks/00-core.md` |

## Два способи запуску

1. **Mac mini + Telegram-бот (рекомендовано)**: постійно увімкнений, відповідає за секунди,
   працює за підпискою Claude без окремого API, токени тільки на ваші повідомлення. Інструкція:
   `bot/README.md`.
2. **Хмарні сесії Claude Code**: планові задачі за розкладом (відповідь у межах години), ті самі
   сценарії і пам'ять. Інструкція нижче і в `scheduled-tasks.md`.

## Архітектура

```
Михайло ──(текст/голосове/файл)──▶ Telegram-чат ◀──(відповіді, PDF, голосові)── помічник
                                        │
             планові задачі Claude Code (ранок, вечір, тиждень, спортзал, вхідні щогодини)
                                        │
                     сесія Claude Code: playbooks/ + bin/ + tools/telegram/tg.sh
                                        │
        Google Drive «Асистент Михайла» · Google Calendar · Gmail · (сайт у цьому репозиторії)
```

Два режими каналу, вибір за змінною `ASSISTANT_BOT_TOKEN` (`config.sh`):

1. **Особистий акаунт** (без бота). Чат = «Збережені повідомлення» (`me`) або будь-який чат
   із `ASSISTANT_INBOX_CHAT`. Помічник пише з вашого ж акаунта з префіксом 🤖. Нічого
   створювати не треба.
2. **Окремий бот** (рекомендовано: видно, де ви, а де помічник). Створіть бота в
   @BotFather, напишіть йому `/start`, задайте `ASSISTANT_BOT_TOKEN` і
   `ASSISTANT_BOT_USERNAME`. Помічник пише від імені бота (Bot API), а читає чат з ботом
   через ваш акаунт (`tg.sh`). Потрібен мережевий дозвіл на `api.telegram.org`.

В обох режимах читання інших чатів, розшифровка голосових і пошук працюють через
`tools/telegram/tg.sh` (особистий акаунт), тому його налаштування обов'язкове.

## Налаштування (один раз)

1. **Telegram особистого акаунта** — за `tools/telegram/README.md`: `TELEGRAM_API_ID`,
   `TELEGRAM_API_HASH`, мережевий дозвіл `*.web.telegram.org` (і `huggingface.co`, `*.hf.co`
   для Whisper, `translate.google.com` для озвучування), потім вхід `tg.sh login` у новій
   сесії та збереження `TELEGRAM_SESSION` у змінних середовища.
2. **Бот (за бажанням)**: `ASSISTANT_BOT_TOKEN`, `ASSISTANT_BOT_USERNAME`, дозвіл
   `api.telegram.org`. Без цих змінних працює режим особистого акаунта.
3. **Змінні середовища (необов'язково)**: `ASSISTANT_TZ` (Europe/Kyiv), `ASSISTANT_INBOX_CHAT`
   (me), `ASSISTANT_MEMORY_FOLDER` (Асистент Михайла).
4. **Setup script середовища** (прискорює кожен запуск):
   ```bash
   pip install -r tools/telegram/requirements.txt
   ```
5. **Планові задачі**: готові назви, розклади і промпти лежать у `scheduled-tasks.md`.
   Створюйте їх в інтерфейсі claude.ai (Scheduled tasks / Routines) з увімкненими
   конекторами Google Drive, Google Calendar і Gmail: задачі, створені зсередини сесії,
   конектори не отримують (п'ять таких уже є, вимкнені, їх можна видалити). Усі працюють у
   часовому поясі Europe/Kyiv і запускають нову сесію з промптом «прочитай
   `tools/assistant/playbooks/<сценарій>.md` і виконай». Вмикати після кроку 1.

   | Задача | Розклад |
   |---|---|
   | Вхідні помічника | щогодини 8:00–22:00 |
   | Ранковий брифінг | щодня 07:30 |
   | Вечірній підсумок | щодня 21:00 |
   | Тижневий огляд | неділя 18:00 |
   | Спортзал | Пн, Ср, Пт 17:30 (змінити під свій графік) |

## Скрипти

```bash
tools/assistant/bin/inbox.sh                 # нові повідомлення від Михайла (JSON), ще не оброблені
tools/assistant/bin/inbox.sh --all 50        # останні 50 повідомлень чату для контексту
tools/assistant/bin/tg-out.sh text "Текст" [--md]     # відповісти Михайлу (бот або особистий акаунт)
tools/assistant/bin/tg-out.sh file тези.pdf "Підпис"  # надіслати файл
tools/assistant/bin/tg-out.sh voice запис.mp3         # надіслати голосове з аудіофайлу
tools/assistant/bin/tg-out.sh say "Текст"             # озвучити й надіслати (режим особистого акаунта)
tools/assistant/bin/md2pdf.sh тези.md [вихід.pdf]     # Markdown → PDF (pandoc + Chromium, стиль pdf.css)
tools/assistant/bin/brief-data.sh            # дані для брифінгу: час, непрочитане, вхідні
```

Як помічник розуміє, що повідомлення вже оброблене: у режимі бота — усе після останнього
повідомлення бота; у режимі особистого акаунта — усе після останнього повідомлення з 🤖
(або після того, на яке воно відповідало). Тому кожна обробка закінчується відповіддю.

## Пам'ять у Google Drive

Папка «Асистент Михайла» з Markdown-файлами: `00 Профіль.md`, `01 Цілі.md`, `02 Задачі.md`,
`03 Звички і спорт.md`, `04 Читання.md`, `05 Рішення.md`, `06 Люди.md`, `07 Компанія.md`,
`Журнал YYYY-MM.md`, підпапки `Зустрічі`, `Тижні`, `Документи`, `Вхідні` (сюди можна класти
записи Plaud). Початкові шаблони лежать у `memory-template/`. На Mac mini папка синхронізована
застосунком Google Drive, і бот редагує файли напряму; хмарні сесії читають їх через конектор.
Детальні правила: `playbooks/00-core.md`.

## Plaud

Основний шлях: офіційний **Plaud MCP** (`https://mcp.plaud.ai/mcp`, вхід через OAuth, потрібен
увімкнений Plaud Cloud Sync). Він дає помічнику список записів, транскрипти й резюме прямо з
хмари Plaud, без пересилання файлів.

- **claude.ai (хмарні сесії)**: Налаштування → Connectors → додати Plaud з каталогу конекторів
  або «Add custom connector» з URL `https://mcp.plaud.ai/mcp`, далі увійти в Plaud.
- **Mac mini (локальний бот)**: у терміналі
  ```bash
  claude mcp add --transport http plaud https://mcp.plaud.ai/mcp
  claude            # у сесії команда /mcp → Plaud → увійти в браузері
  ```
  або інсталятор Plaud: `npx -y @plaud-ai/mcp@latest install`.

Запасний шлях: поділитися записом або транскриптом у Telegram (у чат з помічником) або
покласти у Drive-папку «Асистент Михайла/Вхідні». Автоматично: Zapier «Plaud → Google Drive»
кладе кожен новий транскрипт у цю папку. Сценарій обробки: `playbooks/meeting-notes.md`.

## Безпека

- Помічник пише іншим людям, видаляє події чи файли тільки після явного «так» від Михайла.
- Ключі й сесії тільки у змінних середовища. У репозиторій нічого особистого не потрапляє.
- Відкликати доступ до Telegram: Налаштування → Пристрої → завершити сеанс «Claude Code».

## Наступний етап: миттєві відповіді

Зараз помічник відповідає в межах години (планова задача). Для відповіді за секунди
потрібна постійно увімкнена ланка: Telegram-бот на невеликому сервері або в Make/n8n, що
отримує повідомлення через webhook і передає їх у Claude API, далі ті самі сценарії.
