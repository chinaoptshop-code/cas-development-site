# Як писати статтю блогу (для автоматизації і для людей)

Статті живуть у `tools/blog/articles/<slug>.json`; сторінки збирає `tools/blog/build.py`.
Беклог тем — `tools/blog/topics.json` (`status`: `todo` → `draft` → `published`).

## Порядок

1. Взяти першу тему зі `status: "todo"` у `topics.json`.
2. Написати `tools/blog/articles/<slug>.json` за схемою з шапки `build.py`
   (мова, заголовок, `description` до 160 символів з ключовою фразою, `lead`, `body`, 3–4 FAQ).
   `date` — сьогоднішня; `service` — з теми; `photo` — наявне фото з `img/p/*-900.webp`,
   яке вже стоїть на сторінці цієї послуги (не Osocor).
3. `python3 tools/blog/build.py --check` — має бути `OK`.
4. Поставити темі `status: "draft"` і надіслати Михайлу прев'ю (заголовок, опис, текст) на погодження.
5. Лише після «ОК» Михайла: `python3 tools/blog/build.py`, `status: "published"`, коміт і пуш
   (код у `main` викладає хмарна сесія — інші сесії дають гілку `blog/<slug>`).

## Правила тексту

- 600–900 слів (мінімум 450 перевіряє `--check`), 5–8 розділів `h2`, хоча б один список.
- Ключова фраза теми — у `title`, `description`, `lead` і одному `h2`; без переспаму.
- `<title>` ≤60 символів (перевіряє `--check`): якщо `title` (H1) довший — додай `seo_title` з ключем на початку,
  без води; « | CAS» лише якщо влазить.
- Пишемо як студія для клієнта: просто, конкретно, без води й без «ми найкращі».
- Ціни — лише підтверджені (CLAUDE.md, «Сайт: UI-kit і правила»). Розрахунки — тільки множенням
  підтверджених ставок на площу, з приміткою, що точну суму дає кошторис.
- Не вигадувати: кейси, імена клієнтів, відгуки, терміни в днях, відсотки, статистику, нормативи.
- Не згадувати Osocor/Osokorky, конкурентів, політику.
- Українська — для `uk`, російська — для `ru`; `pair` — slug тієї ж статті іншою мовою, якщо є.
- Наприкінці — абзац про те, як працює CAS (проєкт, кошторис, один менеджер, звіти, гарантія 12 міс.).
